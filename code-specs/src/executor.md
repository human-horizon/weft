# Specification: executor.ts

## Обзор

Модуль реализует выполнение пайплайнов (`PipelineImpl`) — последовательности шагов, которые можно компоновать, параллелизировать и ветвить.

## Публичный API

### Класс `PipelineImpl<FinalCtx, InitialCtx>`

Публичная имплементация интерфейса `Pipeline`.

#### Конструктор

```ts
new PipelineImpl<FinalCtx, InitialCtx>(steps: Step[])
```

- **Параметры**:
  - `steps` — массив шагов пайплайна
- **Эффекты**: создаёт экземпляр пайплайна

#### Метод `run`

```ts
async run(ctx: InitialCtx, opts?: RunOpts): Promise<FinalCtx>
```

Выполняет пайплайн с начальным контекстом.

**Параметры**:
- `ctx` — начальный контекст выполнения
- `opts`:
  - `signal` — `AbortSignal` для отмены
  - `failFast` — `true|false`, продолжить после ошибки шага
  - `dryRun` — `true|false`, сухой запуск без реального выполнения

**Возвращает**:
- `FinalCtx` — итоговый контекст после всех шагов

**Поведение**:
1. В режиме `dryRun` выводит список шагов и завершается
2. Показывает дерево пайплайна перед выполнением
3. Последовательно выполняет шаги
4. При ошибке шага:
   - Если шаг поддерживает продолжение (`opts.continueOnError`) и `failFast = true` — пропускает шаг
   - Иначе — выбрасывает ошибку
5. В блоке `finally` очищает сессии агента

---

## Типы шагов

Все шаги реализуют интерфейс `Step`.

| `kind` | Описание |
|--------|----------|
| `"prompt"` | Выполнение промпта для LLM |
| `"step"` | Выполнение JS-функции |
| `"when"` | Условная ветка |
| `"parallel"` | Параллельные пайплайны |
| `"use"` | Вложенный пайплайн |

## Детали реализации

### `executeStep`

Диспетчер, выбирает обработчик по `step.kind`.

### `executePrompt`

Выполняет промпт для LLM.

**Последовательность**:
1. Генерирует промпт из контекста
2. Выводит заголовки с разделителями
3. Вызывает `invokeWithSchema` или `invokeWithoutSchema`
4. Выводит результат
5. Обновляет контекст ключом `step.name`

**Параметры**:
- `step`:
  - `name` — имя шага
  - `fn` — функция генерации промпта
  - `opts`:
    - `schema` — Zod-схема для проверки результата
    - `session` — идентификатор сессии
    - `model` — тег модели (`medium`, `fast` и т.д.)
    - `thinking` — режим рассуждений
- `ctx` — контекст для `fn`
- `runOpts`:
  - `signal` — сигнал для отмены
  - `timeout` — время выполнения в `ms|s|m`

### `executeJsStep`

Выполняет JS-функцию из шага.

**Параметры**:
- `step`:
  - `name` — имя шага
  - `fn` — функция `ctx => Record<string, unknown>`
  - `opts` — опции `StepOpts` (retry и т.д.)
- `ctx` — контекст

### `executeWhen`

Реализует условие `when`.

**Последовательность**:
1. Вычисляет `predicate(ctx)`
2. Выбирает ветку `then` или `else`
3. Последовательно выполняет шаги из выбранной ветки
4. Возвращает результат последнего шага

### `executeParallel`

Запускает пайплайны параллельно.

**Последовательность**:
1. Берёт ключи `step.tasks`
2. Для каждой задачи:
   - Последовательно выполняет шаги пайплайна
3. Собирает все контексты
4. Объединяет их в итоговый контекст

### `executeJsStep` (step)

Выполняет JS-функцию из шага.

**Параметры**:
- `step`:
  - `name` — имя шага
  - `fn` — функция `ctx => Record<string, unknown>`
  - `opts` — опции `StepOpts` (retry и т.д.)
- `ctx` — контекст

### `executeParallel`

Запускает пайплайны параллельно.

**Последовательность**:
1. Берёт ключи `step.tasks`
2. Для каждой задачи:
   - Последовательно выполняет шаги пайплайна
3. Собирает все контексты
4. Объединяет их в итоговый контекст

## Вспомогательные методы

### `withRetry`

Повторяет вызов при ошибке.

**Параметры**:
- `opts`:
  - `retry` — макс. попыток (по умолчанию 0)
  - `retryDelay` — задержка между попытками (по умолчанию 1000ms)
  - `retryBackoff` — `"exponential"` или `"linear"`
- `fn` — функция для повторения

**Поведение**:
- Если ошибка:
  - Ждёт `retryDelay`
  - Если `retryBackoff === "exponential"` — удваивает задержку
  - Если `retryBackoff === "linear"` — прибавляет `retryDelay`
- После всех попыток выбрасывает ошибку

### `withTimeout`

Ограничивает время выполнения.

**Параметры**:
- `timeout` — время в `ms|s|m` или `undefined`
- `parentSignal` — сигнал родителя для отмены
- `fn` — асинхронная функция

**Поведение**:
- Создает `AbortController`
- Запускает таймер на `timeout`
- Подписывается на `abort` родителя
- Возвращает результат или ошибку `AbortError`
- Очищает таймер в `finally`

### `dryRun`

Показывает список шагов без выполнения.

**Поведение**:
- Выводит `├──` или `└──` для каждого шага
- Показывает название и тип

### `showPipelineTree`

Рисует дерево пайплайна.

**Поведение**:
- Вызывает `renderSteps` с пустым префиксом
- Выводит заголовок `⚡ Pipeline plan:`

### `renderSteps`

Рекурсивно рисует дерево.

**Параметры**:
- `steps` — массив шагов
- `prefix` — префикс для отступа

**Поведение**:
- Для каждого шага:
  - Выбирает префикс `├──` или `└──`
  - Вызывает специализированный рендерер
- Для `when`:
  - Рендерит `then`
  - Если есть `else`, рендерит его отдельно

### `renderPromptStep`

Рисует шаг `prompt`.

**Параметры**:
- `step` — шаг
- `prefix`, `connector`, `childPrefix` — для отступа

**Поведение**:
- Вызывает `resolveModel` для отображения имени модели
- Показывает `thinking` и `session` если есть

## Вспомогательные функции

### `isContinuingStep`

Тайп-гвард: проверяет, поддерживает ли шаг продолжение.

```ts
function isContinuingStep(step: Step): step is ContinuingStep
```

**Возвращает**: `true` если `kind === "prompt"` или `kind === "step"`

### `sleep`

Задержка в `ms`.

```ts
function sleep(ms: number): Promise<void>
```

### `parseHumanTime`

Парсит строку `"100ms"`, `"1s"`, `"1m"`.

```ts
function parseHumanTime(input: string): number
```

**Возвращает**: время в `ms`

**Поведение**:
- Использует регулярку `/^(\d+)(ms|s|m)$/`
- Если формат неверный — выбрасывает ошибку

## Цветная консоль

Использует ANSI-коды для вывода.

```ts
const isColour = process.env.FORCE_COLOR || (process.env.TERM && process.env.TERM !== "dumb");
```

Функции:
- `dim(s)` — серый (`\x1b[2m`)
- `cyan(s)` — голубой (`\x1b[36m`)
- `green(s)` — зелёный (`\x1b[32m`)
- `yellow(s)` — жёлтый (`\x1b[33m`)
- `bold(s)` — жирный (`\x1b[1m`)

## Инварианты

1. Контекст всегда расширяется: `{ ...ctx, [step.name]: result }`
2. Ошибки шагов не прерывают пайплайн если `continueOnError = true`
3. Сигнал `AbortSignal` останавливает выполнение
4. Тайм-ауты корректно отменяются в `finally`
5. Сессии агента очищаются в `finally`
