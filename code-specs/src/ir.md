# IR (Internal Representation) — Спецификация

## Обзор

Модуль `ir.ts` определяет **внутреннее представление (Internal Representation)** шагов конвейера (pipeline) в системе Human Horizon. Файл содержит типы для различных видов шагов, используемых в pipeline-архитектуре.

Все шаги являются дискриминируемыми союнами с поле-дискриминатором `kind`, что позволяет безопасно различать типы шагов на основе их значения.

## Публичный API

### Типы шагов

#### `PromptStep`

Представляет шаг, выполняющий вывод промпта.

```typescript
interface PromptStep {
  kind: "prompt";
  name: string;
  fn: (ctx: any) => string;
  opts: PromptOpts & { schema?: z.ZodType };
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `"prompt"` | Дискриминирующее значение, идентифицирующее тип шага |
| `name` | `string` | Имя шага (логическое обозначение) |
| `fn` | `(ctx: any) => string` | Функция, возвращающая строку промпта. Принимает контекст выполнения |
| `opts` | `PromptOpts & { schema?: z.ZodType }` | Опции шага с возможной схемой Zod для валидации |

#### `StepStep`

Представляет шаг выполнения произвольной логики.

```typescript
interface StepStep {
  kind: "step";
  name: string;
  fn: (ctx: any) => any;
  opts: StepOpts;
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `"step"` | Дискриминирующее значение |
| `name` | `string` | Имя шага |
| `fn` | `(ctx: any) => any` | Функция произвольной логики, возвращающая любое значение |
| `opts` | `StepOpts` | Опции шага |

#### `WhenStep`

Представляет условный шаг с ветвлением по предикату.

```typescript
interface WhenStep {
  kind: "when";
  predicate: (ctx: any) => boolean;
  then: Step[];
  else: Step[];
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `"when"` | Дискриминирующее значение |
| `predicate` | `(ctx: any) => boolean` | Предикат для ветвления логики |
| `then` | `Step[]` | Шаги, выполняемые при истинности предиката |
| `else` | `Step[]` | Шаги, выполняемые при ложности предиката |

#### `ParallelStep`

Представляет параллельный шаг с задачами.

```typescript
interface ParallelStep {
  kind: "parallel";
  tasks: Record<string, Step[]>;
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `"parallel"` | Дискриминирующее значение |
| `tasks` | `Record<string, Step[]>` | Запись, где ключ — имя задачи, значение — массив шагов для параллельного выполнения |

#### `UseStep`

Представляет шаг использования конвейера.

```typescript
interface UseStep {
  kind: "use";
  pipeline: Pipeline<any>;
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `kind` | `"use"` | Дискриминирующее значение |
| `pipeline` | `Pipeline<any>` | Конвейер, используемый в шаге |

### Общий тип `Step`

```typescript
type Step =
  | PromptStep
  | StepStep
  | WhenStep
  | ParallelStep
  | UseStep;
```

Тип `Step` является дискриминируемым союзом всех возможных типов шагов. Дискриминатор `kind` позволяет безопасную работу со значениями типа `Step` с использованием `switch`-выражений.

## Типы из `./types`

Модуль `ir.ts` экспортирует следующие типы из модуля `./types.js`:

- `PromptOpts` — опции для промпт-шагов
- `StepOpts` — опции для шагов
- `Pipeline<T, E>` — тип конвейера с параметрами результата и ошибки

Также используется тип `z.ZodType` из библиотеки Zod для схем валидации.

## Поведение

### Дискриминируемое союзство

Все типы шагов используют дискриминирующее поле `kind`, содержащее константные строковые значения:

- `"prompt"` — шаг промпта
- `"step"` — шаг произвольной логики
- `"when"` — условный шаг
- `"parallel"` — параллельный шаг
- `"use"` — шаг использования конвейера

Это обеспечивает:
1. Безопасное различение типов шагов через `kind`
2. Возможность использовать `switch`-выражения для обработки разных типов
3. Отсутствие необходимости в `any` или `as` для типизации

### Функциональный стиль

Каждый тип шага содержит поле `fn` — функцию, которая:

- Принимает контекст выполнения (`ctx`)
- Возвращает результат выполнения шага

Контекст (`ctx`) является универсальным типом (`any`), что позволяет максимальной гибкости при реализации шагов. Для строгой типизации контекста рекомендуется использовать специализированные типы в конкретных реализациях.

### Опции

Каждый шаг содержит поле `opts` с опциями:

- Для `PromptStep`: `PromptOpts & { schema?: z.ZodType }`
- Для `StepStep`: `StepOpts`
- Для `WhenStep`: (нет явного `opts`)
- Для `ParallelStep`: (нет явного `opts`)
- Для `UseStep`: (нет явного `opts`)

## Важные детали реализации

### Импорт и зависимости

Модуль импортирует только то, что необходимо:

- `z.ZodType` из `zod` — используется опционально для схем валидации
- `PromptOpts`, `StepOpts`, `Pipeline` из `./types` — типы опций и конвейера

Использование `import type` для типовых импортов предотвращает побочные эффекты при импорте.

### Отсутствие глобального состояния

Модуль не содержит глобальных мутабельных переменных. Все состояния инкапсулированы в объектах типов шагов.

### Нет скрытой магии

- Нет автоматической регистрации шагов
- Нет неявного DI (dependency injection)
- Нет моно-патчинга
- Нет скрытых побочных эффектов

### Принцип YAGNI

Только те типы, которые используются в текущей архитектуре конвейера. Никаких предвосхищающих обобщений или абстракций.

### TDD-подход

При разработке новых типов шагов следует подходу Red-Green-Refactor:

1. **Red**: Напишите тесты для нового типа шага
2. **Green**: Реализуйте минимально достаточную логику
3. **Refactor**: Упростите код, сохраняя тестируемость

### Валидация

Для `PromptStep` используется опциональная схема Zod. Это соответствует принципу "parse, don't validate" — невалидные состояния становятся невоплощаемыми через схемы на границах системы.

## Примеры использования

### Создание шага промпта

```typescript
const promptStep: PromptStep = {
  kind: "prompt",
  name: "userInput",
  fn: (ctx) => ctx.prompt(),
  opts: {
    schema: z.string().min(1)
  }
};
```

### Создание условного шага

```typescript
const whenStep: WhenStep = {
  kind: "when",
  predicate: (ctx) => ctx.isReady,
  then: [/* шаги для ready состояния */],
  else: [/* шаги для не-ready состояния */]
};
```

### Создание параллельного шага

```typescript
const parallelStep: ParallelStep = {
  kind: "parallel",
  tasks: {
    fetch: [/* задачи для получения данных */],
    validate: [/* задачи для валидации */]
  }
};
```

## Границы модуля

### Экспортируемые сущности

- `PromptStep` — тип
- `StepStep` — тип
- `WhenStep` — тип
- `ParallelStep` — тип
- `UseStep` — тип
- `Step` — дискриминируемый союз типов

### Неэкспортируемые сущности

- Внутренние реализации шагов (если есть)
- Частичные типы, используемые только внутри модуля

### Зависимости

- `./types` — типы опций и конвейера
- `zod` — опциональные схемы валидации

## Соответствие стандартам Human Horizon

- **Explicit over implicit**: Все поля типов явно описаны, нет неявных соглашений
- **Correctness over convenience**: Дискриминируемый союз вместо `any`
- **Make invalid states unrepresentable**: Схемы Zod предотвращают невалидные данные
- **Local reasoning**: Типы шагов могут быть поняты без знания всего проекта
- **No hidden magic**: Нет глобального состояния, нет автоматической регистрации
- **KISS**: Простая структура типов, без избыточных абстракций
- **SOLID**: Интерфейсы и композиция вместо наследования
