# Specification for `src/types.ts`

## Обзор

Файл `src/types.ts` содержит публичные интерфейсы и тип-утилиты для системы оркестрации рабочих процессов (workflows) в проекте Human Horizon. Эти типы формируют основу API для построения последовательных и параллельных вычислений, обработки промптов LLM и управления состоянием контекста.

---

## Публичные API

### `AgentResult`

Интерфейс, описывающий результат выполнения команды агента.

| Поле | Тип | Описание |
|------|------|----------|
| `stdout` | `string` | Вывод в стандартный поток вывода |
| `stderr` | `string` | Вывод в стандартный поток ошибок |
| `exitCode` | `number` | Код возврата процесса |
| `duration` | `number` | Длительность выполнения в миллисекундах |
| `ok` | `boolean` | Флаг успешного выполнения |

**Использование:** Возвращается из метода `Pipeline.run()` после завершения всех шагов.

---

### `StepOpts`

Опции для шага рабочего процесса.

| Поле | Тип | Описание |
|------|------|----------|
| `retry` | `number` | Количество попыток повторного выполнения (опционально) |
| `retryDelay` | `number` | Задержка между попытками в миллисекундах (опционально) |
| `retryBackoff` | `constant` \| `linear` \| `exponential` | Стратегия увеличения задержки (опционально) |
| `timeout` | `number \| \`${number}ms/s/m\`` | Тайм-аут выполнения (опционально) |
| `continueOnError` | `boolean` | Продолжить выполнение остальных шагов при ошибке (опционально) |

---

### `PromptOpts`

Опции для промпта, наследуются от `StepOpts`.

| Поле | Тип | Описание |
|------|------|----------|
| `session` | `string` | Идентификатор сессии промпта (опционально) |
| `model` | `"simple" \| "medium" \| "high" \| "xhigh" \| "expert" \| string` | Модель или имя промпта (опционально) |
| `thinking` | `"off" \| "minimal" \| "low" \| "medium" \| "high"` | Уровень рефлексии модели (опционально) |
| `schema` | `z.ZodType` | Схема валидации ответа (опционально) |

---

### `RunOpts`

Опции для запуска пайплайна.

| Поле | Тип | Описание |
|------|------|----------|
| `timeout` | `number \| \`${number}ms/s/m\`` | Общий тайм-аут выполнения (опционально) |
| `failFast` | `boolean` | Остановить выполнение при первой ошибке (опционально) |
| `dryRun` | `boolean` | Режим предпросмотра без реального выполнения (опционально) |
| `signal` | `AbortSignal` | Сигнал для отмены выполнения (опционально) |

---

### `Pipeline<T, U>`

Общий интерфейс для пайплайна (сборки вычислений).

| Параметр | Описание |
|----------|----------|
| `T` | Тип финального контекста после выполнения |
| `U` | Тип начального контекста перед выполнением |

**Методы:**

| Метод | Описание |
|-------|----------|
| `run(ctx, opts?)` | Выполняет пайплайн, возвращает `Promise<T>` |

---

### `Workflow<T, U>`

Интерфейс конструктора рабочих процессов с методами для построения вычислений.

| Параметр | Описание |
|----------|----------|
| `T` | Тип контекста после выполнения всех шагов |
| `U` | Тип начального контекста |

**Методы:**

| Метод | Описание | Возврат |
|-------|----------|---------|
| `prompt(name, fn, opts?)` | Добавляет шаг с вызовом LLM. Возвращает `Workflow` с расширенным контекстом, включающим результат промпта. | `Workflow<CurrentCtx & { [K in Name]: AgentResult \| z.infer<S> }, InitialCtx>` |
| `step(name, fn, opts?)` | Добавляет шаговую функцию. Возвращает `Workflow` с расширенным контекстом, включающим результат функции. | `Workflow<CurrentCtx & { [K in Name]: Awaited<Out> }, InitialCtx>` |
| `when(predicate)` | Создаёт ветвление по условию. Возвращает `WhenBuilder`. | `WhenBuilder<CurrentCtx>` |
| `parallel(tasks, opts?)` | Запускает параллельное выполнение нескольких под-воркфлоу. Возвращает `Workflow` с объединёнными результатами. | `Workflow<CurrentCtx & MergedStates<Tasks>, InitialCtx>` |
| `use(pipeline)` | Использует готовый пайплайн для расширения контекста. Возвращает `Workflow` с объединёнными контекстами. | `Workflow<CurrentCtx & InnerCtx, InitialCtx>` |
| `build()` | Конвертирует воркфлоу в готовый пайплайн. Возвращает `Pipeline`. | `Pipeline<CurrentCtx, InitialCtx>` |

---

### `WhenBuilder<T>`

Конструктор для построения ветвления по условию.

| Метод | Описание | Возврат |
|-------|----------|---------|
| `then(branch)` | Добавляет ветку, выполняемую при истинности условия. Возвращает `WhenElseBuilder`. | `WhenElseBuilder<T, any>` |
| `end()` | Завершает построение ветвления. Возвращает `Workflow` с объединёнными контекстами. | `Workflow<T & ThenCtx>` |

---

### `WhenElseBuilder<T, ThenCtx>`

Конструктор для построения ветвления с веткой `else`.

| Метод | Описание | Возврат |
|-------|----------|---------|
| `else(branch)` | Добавляет ветку для случая `else`. Возвращает `WhenEndBuilder`. | `WhenEndBuilder<T, ThenCtx, any>` |
| `end()` | Завершает построение ветвления. Возвращает `Workflow` с объединёнными контекстами. | `Workflow<T & ThenCtx>` |

---

### `WhenEndBuilder<T, ThenCtx, ElseCtx>`

Конструктор для завершения ветвления.

| Метод | Описание | Возврат |
|-------|----------|---------|
| `end()` | Завершает построение ветвления. Возвращает `Workflow` с объединёнными контекстами всех веток. | `Workflow<T & ThenCtx & ElseCtx>` |

---

### `MergedStates<Tasks>`

Тип-утилита для объединения состояний параллельных воркфлоу.

**Формула:**
```typescript
type MergedStates<Tasks extends Record<string, Workflow<any>>> = {
  [K in keyof Tasks]: Tasks[K] extends Workflow<infer Ctx> ? Ctx : never;
}[keyof Tasks] extends infer Union
  ? Union extends Record<string, unknown>
    ? { [K in keyof Union]: Union[K] }
    : Record<string, never>
  : Record<string, never>;
```

**Описание:** Вычисляет объединение типов контекстов всех переданных воркфлоу. Используется в методе `Workflow.parallel()`.

## Важные детали реализации

### Типы контекста

Все воркфлоу имеют два параметра контекста:
- `CurrentCtx` — контекст после выполнения предыдущих шагов
- `InitialCtx` — начальный контекст (по умолчанию `Record<string, never>`)

При добавлении шага контекст расширяется:
- Для `prompt()`: добавляется поле с именем промпта и типом `AgentResult` или типом из схемы
- Для `step()`: добавляется поле с именем шага и типом `Awaited<Out>`

### Обработка ошибок

- Ошибки не выбрасываются напрямую — результат выполнения пайплайна содержит флаг `ok` в `AgentResult`
- Опция `continueOnError` позволяет продолжить выполнение при ошибке конкретного шага
- Опция `failFast` останавливает выполнение при первой ошибке

### Параллельное выполнение

Метод `parallel()` принимает запись с ключами-именами и значениями-воркфлоу. Результат объединяется через `MergedStates`.

### Ветвление

Метод `when()` поддерживает построение условных веток через цепочку вызовов `then() → else() → end()`. Каждая ветка принимает фабрику воркфлоу, которая возвращает рабочий процесс.

## Примеры использования

```typescript
// Простой воркфлоу
const simple = workflow
  .step('process', ctx => process(ctx))
  .build();

// Воркфлоу с промптом
const withPrompt = workflow
  .prompt('analyze', ctx => ctx.query)
  .build();

// Параллельное выполнение
const parallel = workflow.parallel({
  fetch: fetchWorkflow,
  parse: parseWorkflow,
});

// Ветвление
const conditional = workflow
  .when(ctx => ctx.flag)
  .then(w => w.step('then-step', () => ...))
  .else(w => w.step('else-step', () => ...))
  .end()
  .build();
```

## Связанные типы

### Зависимости

- `z` — импорт из `zod` (только тип-импорт через `import type`)

### Стандартный набор

Все типы экспортируются через `export interface` или `type` и доступны для импорта.

---

## Примечания

- Используется только `import type` для импорта типов
- Нет префикса `I` в названиях интерфейсов
- Все функции имеют явные типы возвращаемых значений
- Предпочтение отдается union-типам вместо enum
