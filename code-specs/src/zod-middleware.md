# Specification: zod-middleware

## Обзор

Модуль `zod-middleware` предоставляет средства для вызова агента с валидацией ответа по схеме Zod. Реализует паттерн "parse, don't validate" — преобразует неизвестный входной текст в валидированные доменные типы на границах системы.

## Общественный API

### `invokeWithSchema<T>(prompt, schema, opts)`

Вызывает агента и валидирует ответ по предоставленной схеме Zod.

#### Параметры

| Параметр | Тип | Описание |
|----------|-----|----------|
| `prompt` | `string` | Исходный промпт, который отправляется агенту |
| `schema` | `z.ZodType<T>` | Схема Zod для валидации ответа агента |
| `opts` | `{ signal?, session?, model?, thinking? }` | Дополнительные опции |
| `signal` | `AbortSignal?` | Сигнал для отмены запроса |
| `session` | `string?` | Идентификатор сессии |
| `model` | `string?` | Идентификатор модели |
| `thinking` | `string?` | Дополнительные данные для размышления |

#### Возвращаемое значение

`Promise<T>` — валидированное значение типа `T`, соответствующее схеме.

#### Поведение

1. Генерирует описание схемы через `schemaToPrompt(schema)`
2. Формирует полный промпт: `prompt` + `schemaDescription`
3. Вызывает `invokeAgent` с максимальным количеством попыток `1`
4. Извлекает JSON из stdout агента:
   - Сначала пытается найти markdown-блок с JSON
   - Затем пытается найти первый объект `{...}` или массив `[...]` в тексте
   - Если ничего не найдено — возвращает текст как есть
5. Парсит извлечённый текст как JSON
6. Валидирует результат через схему Zod
7. Если валидация или парсинг не удались и попытки остались:
   - Обновляет промпт, добавляя информацию об ошибке
   - Повторяет вызов агента
8. При исчерпании попыток выбрасывает ошибку

#### Логи

Во время выполнения выводятся строки:
- `[weft] agent stdout (N chars):` — первые 500 символов stdout агента
- `[weft] agent stderr:` — stderr агента или "(empty)"
- `[weft] agent exitCode:` — код выхода агента
- `[weft] extracted JSON (N chars):` — первые 300 символов извлечённого JSON

### `invokeWithoutSchema(prompt, opts)`

Вызывает агента без валидации по схеме. Возвращает `AgentResult` напрямую.

#### Возвращаемое значение

`Promise<AgentResult>` — результат вызова агента.

## Внутренние функции

### `extractJson(text: string): string`

Извлекает JSON-текст из строки ответа агента.

#### Стратегия извлечения

1. Ищет markdown-код-блок:
   - Поддерживает оба формата:
     - ```json ... ```
     - ``` ... ``` (без указания языка)
   - Возвращает содержимое блока без маркеров
   - Убирает лишние пробелы в начале/конце

2. Если markdown-блок не найден:
   - Ищет первый объект `{...}` или массив `[...]` в тексте
   - Возвращает найденный блок

3. Если ничего не найдено:
   - Возвращает исходный текст после удаления пробелов в начале/конце
   - Позволяет получить понятную ошибку при парсинге

#### Возвращаемое значение

`string` — извлечённый JSON-текст

## Типы

### `AgentResult`

Внешний тип, импортируемый из `./types.js`. Используется для возврата результата вызова агента.

### `PromptOpts`

Внешний тип, импортируемый из `./types.js`. Опции для вызова агента.

### `schemaToPrompt(schema)`

Функция-утилита из `./schema-to-prompt.js`, возвращающая описание схемы в виде строки. Используется для формирования промпта.

## Поток выполнения

```
┌─────────────────────────────────────────────────────────────────┐
│ invokeWithSchema<T>(prompt, schema, opts)                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  1. maxRetries = 1                                               │
│  2. schemaDescription = schemaToPrompt(schema)                   │
│  3. currentPrompt = prompt + "\n\n" + schemaDescription          │
│                                                                   │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │ for (attempt = 0; attempt <= maxRetries; attempt++) {       │ │
│  │   result = await invokeAgent(currentPrompt, opts)           │ │
│  │                                                               │ │
│  │   ┌─────────────────────────────────────────────────────────┐ │
│  │   │ Логируем stdout, stderr, exitCode агента                │ │
│  │   └─────────────────────────────────────────────────────────┘ │
│  │                                                               │ │
│  │   ┌─────────────────────────────────────────────────────────┐ │
│  │   │ jsonText = extractJson(result.stdout)                   │ │
│  │   │ parsed = JSON.parse(jsonText) as unknown                │ │
│  │   │ return schema.parse(parsed)                             │ │
│  │   └─────────────────────────────────────────────────────────┘ │
│  │                                                               │ │
│  │   catch (err) {                                               │ │
│  │     if (attempt === maxRetries) throw err                    │ │
│  │     currentPrompt = prompt + "\n\n" + schemaDescription +    │ │
│  │       "\n\nPrevious response was invalid: " + String(err) +  │ │
│  │       "\nPlease fix and retry."                               │ │
│  │   }                                                           │ │
│  │ }                                                             │ │
│                                                                   │
│  throw new Error("unreachable")                                  │
└─────────────────────────────────────────────────────────────────┘
```

## Обработка ошибок

### Возможные исключения

1. `Error` от `schema.parse()` — при неудачной валидации по схеме
2. `SyntaxError` от `JSON.parse()` — при неверном JSON-тексте
3. `Error("unreachable")` — если код достигнут (теоретически недостижимо)

### Поведение при ошибке

- При первой ошибке: обновляется `currentPrompt` с информацией об ошибке
- После исчерпания всех попыток: ошибка выбрасывается
- Логи содержат информацию об ошибке агента и извлечённом JSON

## Принципы реализации

### Explicit over implicit

- Ошибки явно представляются через типизированные типы
- Валидация явно выражена через схемы Zod
- Границы между слоями явны (агент → middleware → домен)

### Parse, don't validate

- Входной текст из stdout агента трансформируется в валидированные типы
- На границе системы применяется парсинг + валидация
- Невалидные состояния не могут быть представлены в домене

### KISS

- Простая логика извлечения JSON (markdown-блок → первый объект/массив)
- Минимальное количество попыток (1 retry)
- Нет избыточной абстракции

### YAGNI

- Только то, что нужно текущему использованию
- Нет абстракций без текущего применения

## Архитектурные границы

### Внешние зависимости

- `zod` — библиотека валидации схем
- `./types.js` — типизированные типы `AgentResult`, `PromptOpts`
- `./agent.js` — функция `invokeAgent` для вызова агента
- `./schema-to-prompt.js` — генерация описания схемы

### Локальные функции

- `extractJson` — извлечение JSON из текста
- `invokeWithSchema` — основной экспортируемый метод
- `invokeWithoutSchema` — альтернативный метод без валидации

## Тесты

Модуль должен тестироваться на:

1. Успешный вызов с валидным ответом
2. Извлечение JSON из markdown-блока
3. Извлечение JSON из plain текста
4. Извлечение пустого JSON объекта
5. Валидация успешная
6. Валидация неудачная с retry
7. Исчерпание попыток
8. Отмена по сигналу `AbortSignal`

## Допуски

### TypeScript

- 4-пробелное отступление
- Без точек с запятой
- Одинарные кавычки
- Запятые в конце строк
- Максимум 100 символов в строке
- Никогда `any` — использовать `unknown` с type guards
- Никогда `as` — использовать type guards (кроме `as const`)
- Явные типы возврата у всех функций
- `interface` для объектов, `type` для юнионов
- `import type` для type-only импортов
- `Result<T, E>` для ошибок вместо throwing
- Юнион-типы вместо enums
- Объявления функций на уровне top level, не `const` стрелочные функции
- Деструктуризация параметров объекта когда >3 параметров
- Без префикса `I` на интерфейсах

### Запрещено

- Новый язык, фреймворк, библиотека, инструмент, архитектурный паттерн без разрешения
- Вторичный тестовый фреймворк
- Скрытое глобальное мутабельное состояние
- Имплицитный DI
- Monkey patching
- Недокументированные конвенции
