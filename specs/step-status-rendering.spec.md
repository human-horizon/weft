# weft — статус каждого шага с описанием

## Цель
В консоли нужно видеть, что происходит во время выполнения пайплайна:
- статус каждого шага, а не только промтов;
- понятное человеку описание (label) для каждого типа шага;
- параллельные потоки не перетирают друг друга;
- у каждого инстанса своя корректная длительность (даже при одинаковом имени);
- мгновенный фидбек при старте, не дожидаясь первого реального шага.

## Поведение

1. **Описание генерируется автоматически**, если `description` не указана:
   - `prompt`:    `name (prompt, model-tag)`
   - `step`:      `name (js step)`
   - `when`:      `when (conditional branch)`
   - `parallel`:  `parallel(task1, task2)`
   - `use`:       `use (embedded pipeline)`
   - Пользователь может переопределить через `opts.description`.

2. **Параллельный рендер с уникальными ID**:
   - При `start(label)` создаётся уникальный `InstanceId`, начало фиксируется.
   - `finish(id, ok, error?)` удаляет инстанс и печатает завершение с **собственной**
     длительностью для этого конкретного инстанса.
   - Активная строка показывает счётчик, если несколько инстансов с одинаковым
     label активны одновременно: `draft (×3), other (×2)`.

3. **Спиннер с мгновенным фидбеком**:
   - При входе в `pipeline.run()` синхронно стартует `starting pipeline` —
     пользователь видит спиннер даже во время env-лoadинга, подключения к БД
     и прочей подготовки до первого `executeStep`.

4. **Защита от пустого описания**:
   - Если `stepLabel(step)` возвращает пустую строку (неизвестный kind) —
     executor кидает ошибку.

## Изменения vs 0.5.5

- `src/executor.ts`:
  - `StepStatusRenderer` использует `Map<InstanceId, number>` для стартов и
    `Map<InstanceId, string>` для labels. Внутри `counts: Map<string, number>`
    для счётчика дубликатов.
  - `start(label)` возвращает `InstanceId`, `finish(id, ...)` принимает его.
  - Удалён неиспользуемый импорт `resolveModel`.
  - В `run()` добавлен синхронный `statusRenderer.start("starting pipeline")`
    до первого шага, финиш в `finally`.
- `package.json`: `0.5.5 → 0.5.6`.

## Демонстрация (5 параллельных одинаковых шагов)

```
[weft] → starting pipeline ⠋
[weft] → starting pipeline, parallel(h1, h2, h3, h4, h5) ⠋
[weft] → starting pipeline, parallel(h1, h2, h3, h4, h5), draft (...) ⠋
[weft] → starting pipeline, parallel(h1, h2, h3, h4, h5), draft (...) (×5) ⠹
…
[weft] ✓ draft (...) (2.2s)
[weft] → …, draft (...) (×4) ⠇
[weft] ✓ draft (...) (2.4s)
[weft] → …, draft (...) (×3) ⠏
[weft] ✓ draft (...) (2.4s)
[weft] → …, draft (...) (×2) ⠋
[weft] ✓ draft (...) (2.5s)
[weft] → …, draft (...) ⠸
[weft] ✓ draft (...) (3.3s)
[weft] ✓ parallel(h1, h2, h3, h4, h5) (3.3s)
[weft] ✓ starting pipeline (3.3s)
```

Каждый из 5 параллельных `draft` имеет **собственную** корректную длительность,
вместо единого `0ms` для всех, кроме первого (баг 0.5.5).
