# weft — статус каждого шага с описанием

## Цель
Раньше в консоли статус выводился только для промтов: `[weft] → prompt-name ⠋`. Все остальные
шаги (js-step, when, parallel, use) выполнялись молча, и пользователь не понимал, что
происходит. Нужно: каждый тип шага выводит статус с понятным человеку описанием, и при
параллельном исполнении шаги не перетирают друг друга.

## Поведение

1. **Описание генерируется автоматически**, если `description` не указана в opts.
   - `prompt`: `name (prompt, model-tag)`
   - `step`:   `name (js step)`
   - `when`:   `when (conditional branch)`
   - `parallel`: `parallel(task1, task2)`
   - `use`:    `use (embedded pipeline)`

2. **Пользователь может переопределить** через `opts.description` (необязательное поле).

3. **Параллельный рендер**: одна глобальная статусная строка показывает все
   активные шаги через запятую с одним вращающимся спиннером. Завершения
   печатаются на отдельных строках.
   Пример:
   ```
   [weft] → parallel(a, b) ⠋
   [weft] → parallel(a, b), p1 (prompt, simple) ⠙
   [weft] → parallel(a, b), p1 (prompt, simple), p2 (prompt, simple) ⠹
   [weft] ✓ p1 (prompt, simple) (2.2s)
   [weft] → parallel(a, b), p2 (prompt, simple) ⠸
   [weft] ✓ p2 (prompt, simple) (2.4s)
   [weft] ✓ parallel(a, b) (2.5s)
   ```

4. **Защита от пустого описания**: если по какой-то причине итоговый
   label получился пустой (неизвестный kind), executor кидает ошибку
   `Step has no status description. Add "description" to opts or use a supported step kind.`
   Это закрывает требование «если описания нет — кидать ошибку»: для всех
   штатных типов шагов описание существует всегда, а на нештатных —
   fail-fast.

5. **Минимальные изменения в API**: `description` добавлено как
   опциональное поле в `StepOpts`. Никакой миграции в существующих
   pipeline-ах не требуется.

## Изменения
- `src/types.ts` — добавлено `description?: string` в `StepOpts`.
- `src/executor.ts` — новый класс `StepStatusRenderer` (одна статусная
  строка + спиннер, поддержка параллельного исполнения), функции
  `stepLabel` (генерация label) и `requireStepLabel` (throw на пустом
  label), `executeStep` обёрнут в renderer.
- `src/builder.ts` — без изменений.
- `tests/` — без изменений, существующие 39 тестов проходят.

## Known limitations
- Если в opts.description пустая строка, она игнорируется и используется
  сгенерированный label. Это намеренное поведение: `description` —
  способ переопределить автогенерацию, а не заменить её на пустоту.
- Параллельная статусная строка может быть длинной, если много шагов
  одновременно. В будущем можно ограничить ширину.
